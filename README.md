# アップロード不要の動画圧縮（video-compressor-under20mb）

動画をDiscordに投稿できるサイズ（20MB以下）に圧縮するサイトです。ブラウザの付属機能（WebCodecs）を使って端末の中で圧縮するため、動画はアップロードされません。
共有シートからそのままDiscordに投稿でき、ホーム画面に追加すればオフラインでも起動できます（PWA。アイコン名は「20MB圧縮」）。

**公開URL: [https://maka-u20mb.pages.dev/](https://maka-u20mb.pages.dev/)**（Cloudflare Pages）

---

## なぜ作ったか

- Discordの無料アカウントのアップロード上限は**20MB**です（2026年8月に10MBから引き上げ。**圧縮前のファイルサイズ**で判定）。
  上限は変わる可能性があるため、目標サイズは詳細設定やURLで変えられます（Nitro Basicの50MBなど）。
- iPhoneの「ショートカット」の*メディアをエンコード*では**ビットレートを直接指定できず**、解像度を段階的に下げて当たりを探すしかありません。
  このアプリは**目標サイズから逆算したビットレートを直接指定**して圧縮します。

## 画面

アプリの画面（`index.html`）は3ステップで圧縮します。見出しの「使い方」で説明書（手順の画像・ショートカットのページ・よくある質問・更新情報）を開けます。
ブランチのプレビュー（`<ブランチ名>.maka-u20mb.pages.dev`）では、見出しに版（例: `ver 2026-10-01e`）を出します。

1. **圧縮の仕方を選ぶ**
   - **なるべく圧縮**：720p・30fps・指定ビットレート（初期値 1,200kbps）
   - **画質優先（20MB以内）**：元の解像度とfpsのまま、20MBに収まるなるべく高いビットレート（指定ビットレートを下回らない）
   - **詳しく設定する**：1 と 2 の間に「設定」のステップを足す（解像度・fps・圧縮方法・詳細設定。変えたらこの端末に保存する）。
     2択のときは保存してある設定を使わず、保存もしない
2. **動画を選んでトリミング**：プレビュー・トリミング・予想を出す。
   トリミングの下の「**設定変更簡易メニュー**」で、**その動画だけ**解像度（480p・720p・1080p・元の解像度。元より大きくはできない）・fps・圧縮方法・ファイル名を変えられる。
   - 「圧縮ルール」は、今の設定が2択のどちらかと同じならその名前、違えば「カスタム」と出す
   - 先行圧縮が済んで押せばすぐ出せるときは、「圧縮する」ボタンの2行目に「（◯MBで即出力します）」を出す
   - 20MB以下の動画は「圧縮せずに、このまま共有・保存へ」で進める
   - 720p・1080p ではない 1080p 以下の動画（画面録画など）は、元の解像度のまま圧縮する
3. **共有・保存**：「Discord等に共有」「保存」を大きく出す（iPhone・iPadでは「Discord等に共有・動画保存」の1つ。共有シートの「ビデオを保存」で写真に保存できるため）。
   結果は2行（解像度/fps/長さ/実際のビットレート/VBR・CBR/圧縮時間、元の大きさ → 書き出した大きさ（削減率））。
   「← 戻る」で範囲や設定を変えてやり直し、「同じ設定で別の動画を圧縮」で 2 に戻る

- 上の手順の帯で前のステップに戻れます（圧縮中は戻れません。キャンセルすると 2 に戻ります）。
- URLに設定のパラメータがあるとき（ショートカットから開いたときなど）は、その設定の「詳しく設定する」で 2 から始めます。`auto=on` なら動画を選んだらそのまま圧縮します。
- トリミングのバーは、左右のつまみで範囲を決め、細い線（再生位置）を動かすか何もない所を触るとシークします。

### 詳細設定

目標サイズ・許容する最小サイズ・指定ビットレート（720p / 1080p）・動画を選んだらすぐ圧縮・音声の有無・ファイル名の指定を変えられます。
画面で変えた設定はこの端末のブラウザに保存されます。URLに設定のパラメータが1つでもあるときは、保存してある設定は使わず、初期値にURLの設定だけを重ねます（保存してある設定は消しません）。
「現在の設定を記憶したURLを生成してコピー」で、今の設定をURLパラメータにしたURLをコピーできます（既定値と同じ項目は省きます）。

**ファイル名の指定**（既定はオフ）：オンにすると、選んだ項目を↑↓で並べた順に「_」でつないだ名前にします（例: `20260926153012_クリップ_720p_20MB_k7mq.mp4`）。

| 項目 | 入る文字 |
| --- | --- |
| 日付 / 日付+時間 | 圧縮した日時（`20260926` / `20260926153012`）。どちらか1つだけ |
| 自由入力 / 自由入力2 | 入力した文字（文字と数字、「-」「_」だけ。10文字まで。空なら飛ばす） |
| ランダム英数字4桁 | 小文字の英字と数字4文字（見間違えやすい 0・o・1・l・i は使わない） |
| 圧縮オプション | `720p_20MB`・`1080p_narubeku`・`元解像度_20MB` など。トリミングのみは `トリミング`、元のまま渡すときは `元のまま` |
| 元のファイル名 | 選んだ動画の名前（拡張子なし） |

## ショートカットと組み合わせる

Nintendo Switchアプリで録画した動画をDiscordに投稿するまでの流れです（詳しくは説明書から開ける `shortcut.html`）。

1. **Switchアプリ**の動画共有 → 共有シート → **自作のショートカット**を実行
2. ショートカットが動画を写真アプリ（またはファイル）に保存し、このアプリを開く
   （ショートカットの最後に「URLを開く」で `https://maka-u20mb.pages.dev/?target=20&res=720` などを開く）
3. アプリで**動画を選択**（ここは手動。iOSはWeb Share Targetに非対応のため、動画を自動で受け取れません）
4. 必要なら**トリミング**して**圧縮する** → **共有**からDiscordに投稿

### URLパラメータ

画面と詳細設定のすべての項目を、URLで最初から選んでおけます。どれも省略でき、省略時は既定値になります。

| パラメータ | 値 | 意味 | 既定 |
| --- | --- | --- | --- |
| `res` | `480` / `720` / `1080` / `source` | 出力解像度（`720p` のような表記も可）。`source`（`original` も可）は元の解像度 | `720` |
| `mode` | `size` / `quality` | `size`＝◯MB以内に圧縮、`quality`＝なるべく圧縮 | `size` |
| `target` | 1〜500 | 目標サイズ（MB） | `20` |
| `preuse` | 50〜100 | 許容する最小サイズ（目標サイズに対する％）。「◯MB以内」で、先行圧縮の大きさがこれ以上なら、すぐ出力する。`100` ですぐ出力しない | `80` |
| `min720` | 100〜50000 | 720pの指定ビットレート（kbps） | `1200` |
| `min1080` | 100〜50000 | 1080pの指定ビットレート（kbps） | `2700` |
| `fps` | `30` / `source` | `30`なら40fpsを超える動画を30fps以下にする（60→30、120→30、50→25）。`source`は元のフレームレートを保つ | `30` |
| `audio` | `on` / `off` | 音声を残すか | `on` |
| `auto` | `on` / `off` | 動画を選んだらすぐ圧縮を始めるか | `off` |
| `name` | `date,text1,opt` など / `off` | ファイル名を指定する（使う項目を並べる順にカンマで区切る。`date`・`datetime`・`text1`・`text2`・`rand`・`opt`・`orig`） | 指定しない |
| `text1` / `text2` | 文字 | ファイル名の自由入力 / 自由入力2 | 空 |

`on` / `off` の代わりに `1` / `0`、`true` / `false` も使えます。範囲外や不明な値は無視して既定値になります。

## 圧縮の方法

**解像度は選んだもので固定**し（元の動画より大きくはしません）、容量は**ビットレートだけ**で調整します。

| 圧縮方法 | 映像ビットレート |
| --- | --- |
| **なるべく圧縮** | その解像度の**指定ビットレート**（既定: 720p＝1,200kbps、1080p＝2,700kbps） |
| **◯MB以内に圧縮** | 指定ビットレートを下回らない範囲で、**目標サイズに収まるなるべく高いビットレート** |

- 「元の解像度」と480pの指定ビットレートは、720pの値を画素数に比例させます。60fpsのまま書き出すときは1.5倍にします。
- 「◯MB以内」の計算：`映像ビットレート = 目標MB × 1,000,000 × 8 × 0.97 ÷ 秒数（トリミング後） − 音声ビットレート`
  - **1MB＝100万バイト**で数え、目標の**97%を狙い**、結果は**目標サイズ「未満」**に収めます（どちらの数え方でも20MBに届きません）
  - 目標を超えたら、実際の大きさからビットレートを計算し直して**最大2回まで圧縮し直します**（指定ビットレートより下げない。前回より3%以上小さくならなければやめる）
- 元動画の実効ビットレート（HEVCなら1.5倍）は超えません。
- すでに目標サイズ以下の動画（トリミングなし）は、**そのまま共有・保存できる状態**になります
  （位置情報が入っている・分からないとき、「音声を残す」がオフで音声があるときは、それを除いて再圧縮なしで書き出します）。
- 「◯MB以内」で解像度もfpsも元のまま、トリミングした元動画が目標に収まる見込みなら、**再エンコードせずにトリミングだけ**します
  （始まりはキーフレームからになりますが、その部分は MP4 のエディットリストで再生しません）。目標を超えたら通常の圧縮に切り替えます。
- エンコードは可変ビットレート（VBR）が基本で、ハードウェアの VBR → ハードウェアの CBR → ソフトウェアの VBR の順に選びます。
  iPhone・Safari（WebKit）は CBR/VBR の指定をエンコーダーに渡さないので、結果に「CBR」「VBR」を出しません。
- 書き出す動画には題名や日付は残しますが、位置情報を含む生のメタデータは除きます。

### 先行圧縮（サイズの予想と即出力）

エンコーダーは映像によって指定のビットレートを守りません（iPhone の 1080p60 のゲーム映像で、2.7Mbps・4.05Mbps のどちらを指定しても約7.5Mbps。Android で 1.2Mbps が 2.4〜2.9Mbps）。そこで、実際に圧縮して測ります。

- 動画を読み込んだら（設定を変えたときも）、**範囲に関係なく動画の最初から最後まで**を指定ビットレートで裏で圧縮します。範囲を変えただけならやり直しません。
  「動画を選んだらすぐ圧縮」がオンのとき・互換モードのときはしません。
- 書き出しは区切りごと（fragmented MP4）に受け取り、1コマごとの大きさ・時刻を読んで、範囲を切り出したときの大きさを正確に数えます。
- 予想の行は「現在の設定：720p/30fps/1分00秒/1.2Mbps」と「→ 7.5MB（予想・先行圧縮 60%）」の2行です。
  押せば先行圧縮から切り出せるときは「（確定・先行圧縮済み）」にし、ビットレートも切り出した大きさから求めた実際の値（3 の結果と同じ）にします。
  目標サイズに収まらない見込みなら、3行目に「◯分◯秒以内で20MBに収まります。」を出し、トリミングの帯を黄色にします。
- 「圧縮する」を押したとき、先行圧縮が範囲の始まりまで届いていれば、範囲の終わりまで続けて**範囲を切り出して結果にします**（再エンコードなし）。
  - 「◯MB以内」では、切り出した大きさが**目標の80%以上・目標未満**のときだけ使います（80%は「許容する最小サイズ」で50〜100%に変えられる）。
    目標いっぱいまで圧縮し直しても画質はほぼ変わらず、指定の約2倍で書き出す端末では何回も圧縮し直すことになるためです。
  - 届いていない・切り出せなかったときは、範囲だけを普通に圧縮します。
- 途中で止めた先行圧縮も、止めたところまで残します。3 から戻って範囲を縮めたときなど、範囲の終わりまで届いていれば使います。
- 指定ビットレートを下げても大きさが変わらない端末では、「この端末ではこれ以上ビットレートを下げられないみたいです。」と出します。

## 処理の仕組み

| | 高速モード（通常） | 互換モード（予備） |
| --- | --- | --- |
| 使う場面 | MP4 / MOV で、端末がデコードできる動画 | それ以外の動画、または高速モードが失敗したとき |
| 仕組み | [Mediabunny](https://mediabunny.dev/) の `Conversion` で動画を直接読み、WebCodecs で変換 | `<video>` を再生しながらフレームを取り出し、`VideoEncoder` で圧縮 |
| 処理時間 | 端末の性能次第で**実時間より速い** | **動画の長さと同じくらい** |

- 映像は H.264 のハードウェアエンコードを優先します。2秒ごとにキーフレームを入れ、moov を先頭に置いた mp4 にします。回転情報は映像に焼き込みます。
- 音声は、元がAACで192kbps以下ならそのまま使い、それ以外はAAC 128kbpsに変換します（変換できない端末では音声なし）。読めない音声（空間オーディオなど）が AAC と一緒に入っていれば AAC を使います。
- 映像と音声は、メインの1本ずつだけを書き出します。
- 画面を表示しているのに進捗が20秒止まったら、互換モードに切り替えます。
- 圧縮中に別のアプリに切り替えて失敗したときは、画面に戻ってから同じ方式で最初からやり直します（最大3回）。iPhone でデコーダーが固まったときは、Safari を開き直すよう案内します。
- **共有**は `navigator.share` で共有シートを開きます（ない環境や断られたときはダウンロード）。**保存**は `<a download>` でダウンロードします。

## うまく動かないとき（診断情報）

処理の経過は画面のいちばん下の「**診断情報**」で見られます（本番では、エラーで終わったときなどに自動で開きます。URLに `?debug=1` を付けるといつでも表示）。
端末の種類、動画の形式、試したエンコード設定、処理の経過を記録し、動画の中身やファイル名は含みません。「コピー」で写して、X（[@inkaroma0431](https://x.com/inkaroma0431)）あるいはDiscordに送ってください。

## 注意

- **長い動画は目標サイズに収まりません。** 既定の指定ビットレートと音声128kbpsで、20MBに収まる長さの目安は **720pで約1分56秒、1080pで約54秒**（50MBなら約4分52秒・約2分17秒）です。
  長いときは、トリミングする / 720pにする / 指定ビットレートを下げる / 音声をオフにする / 目標サイズを上げる、のどれかをしてください。
- 圧縮中は画面を開いたままにしてください（互換モードは特に。iPhone の低電力モードでは互換モードの再生が許可されないことがあります）。
- **iPhoneで写真アプリから選ぶと、iOSが動画を変換してから渡します**（H.264・HDRなし・30fps）。
  60fpsのまま使うには、写真アプリの共有から「"ファイル"に保存」して「ファイルを選択」から選び、「60fpsの動画は30fpsにする」をオフにします（圧縮後はHDRなし）。
- Android で、Googleフォトの端末に保存されていない大きい動画は、選んでも何も起きないことがあります。先に端末に保存してから選んでください。
- 本サイトは現状のまま無保証で提供しており、動作や圧縮結果を保証するものではありません。

## 開発・公開

公開するのは **`public/` フォルダの中身だけ**で、ビルドは不要です。Cloudflare Pages（プロジェクト `maka-u20mb`）が GitHub と連携していて、
`main` に入ると本番に、ほかのブランチは `<ブランチ名>.maka-u20mb.pages.dev` のプレビューに公開されます（Build output directory は `public`、Build command は空）。

```bash
python3 -m http.server 8000 -d public   # 手元で確認（Service Workerを使うためhttpで配信する）→ http://localhost:8000/
```

- `public/` のファイルを変えたときは、コミットの前に **`npm run bump`** で版を上げます（`public/sw.js` のキャッシュ名と `public/js/constants.js` の `APP_VERSION`）。
  キャッシュ名を上げないと、利用者は前の版のままになります。
- `public/js/` にファイルを足したときは、`public/sw.js` の `ASSETS` にも足します（オフラインで起動できなくなるため）。
- Service Worker は、本番では**キャッシュ優先**（更新は裏で取得して次に開いたときに反映）、プレビューと localhost では**ネット優先**（3秒応答がなければキャッシュ）です。動画は Service Worker を通しません。
- `public/vendor/mediabunny.min.js` は、Mediabunny から使う機能と入力形式（MP4 / MOV）だけを束ねたものです。`npm install && npm run build:vendor` で作り直します（含める機能は `tools/mediabunny-entry.js`）。
- 説明書の画像（`public/help/step-1〜4.webp`・`sc-url.webp`）は `node tools/make-help-images.js` で作ります（画面を変えたら作り直し、変わらなかった画像は戻す）。

### テスト

実際のブラウザでアプリを動かし、動画を圧縮して結果を確かめます（`tools/test/`。[Playwright](https://playwright.dev/)）。
必要なもの：Node.js、ffmpeg、H.264 と AAC を扱える Chrome（Chromium では動きません）。

```sh
npm install
npm run test:videos   # テスト用の動画を作る（最初の1回だけ。約2分・約470MB）
npm test              # すべてのテスト（約13分）
npm test -- strip.spec.js   # 一部だけ
npm run test:unit     # calc.js・fmp4.js の単体テスト（ブラウザ不要）
npm run lint          # ESLint
```

環境変数：`FFMPEG`（ffmpeg の場所）、`CHROME_PATH`（Chrome の実行ファイル）、`CHROME_ARGS`（GPU のない Linux では `--disable-gpu`）、`WORKERS`（同時に動かす数。既定1）。

| ファイル | 確かめること |
| --- | --- |
| `matrix.spec.js` | いろいろな動画（720p・1080p・縦長・回転・画面録画）が20MB未満・正しい大きさ・音声ありになる（PC・Android・iPhone の画面） |
| `edge.spec.js` | 小さい・短い・長い動画、4K、音声の種類、WebM、HEVC、壊れたファイル、ファイル名 |
| `strip.spec.js` | 位置情報・音声の除去、トリミングのみ（再圧縮なし）と通常の圧縮への切り替え |
| `probe.spec.js` | 先行圧縮：予想、押したときに使う条件と切り出し、やり直し、3 から戻ったときに残すこと |
| `ui.spec.js` | 圧縮後・やり直し・キャンセルの画面、ファイル名、設定の保存、使い方、共有・保存、シーク |
| `settings.spec.js` | 設定の保存・読み込み・初期値に戻す、URL の読み取りと作成 |
| `robustness.spec.js` | 別のアプリへの切り替え、Android で読めないとき、互換モードの失敗・キャンセル、画面を暗くしない設定 |
| `sw.spec.js` | Service Worker のキャッシュ、オフラインでの起動 |
| `selftest.spec.js` | 自己テストのページが最後まで動き、失敗がないこと |
| `easy.spec.js` | 3ステップの画面：2択の設定、その動画だけの設定、設定のステップ、URLで開いたとき、ステップの切り替え、即出力 |

中身の処理はテストを動かす Chrome のものなので、Android・iPhone の実機での確認は別に必要です。

### 実機での自己テスト（`selftest.html`）

実機で `https://maka-u20mb.pages.dev/selftest.html` を開くと、その端末で圧縮を試せます（どこからもリンクしていません）。
テスト用の動画をその場で作り、本番の画面を iframe で開いて判定します。「自動テスト」「別のアプリへの切り替え」「先行圧縮」「新しい画面（3ステップ）」「手元の動画」の5種類があり、
「結果をコピー」で失敗した項目の診断情報ごとコピーできます。設定は URL で渡すので、端末に保存してある設定は変えません。

### コードの構成（`public/js/`）

`index.html` が `js/main.js` を読み込み、`main.js` がほかのモジュールを読み込みます。

| モジュール | 役割 |
| --- | --- |
| `main.js` | 入口。画面の配線と起動、テスト用の `window.__compressor` |
| `constants.js` | 定数（`APP_VERSION` を含む） |
| `calc.js` | 計算だけの関数：圧縮の計画（`makePlan`）、先行圧縮からの予想・切り出す大きさ、表示の書式、圧縮1回ぶんのあとの判断（`retryAfterSize`・`recoveryAfterFailure`）など |
| `dom.js` / `state.js` | 画面の要素（`els`）と、アプリの状態（`state`） |
| `util.js` | 診断情報への記録、処理の中断（job）、進捗の表示 |
| `settings.js` | 設定の一覧（`SETTING_DEFS`）、保存・読み込み、URL の読み取りと作成 |
| `naming.js` | 書き出す動画のファイル名 |
| `media.js` | 端末の対応判定、動画のメタ情報、音声の扱い、Mediabunny の入力を開く・閉じる |
| `load.js` | 選んだ動画の読み込みと解析 |
| `plan.js` | 今の画面の設定での計画（`currentPlan`） |
| `precompress.js` | 先行圧縮（始め方・止め方・持つルール、押したら範囲を切り出して結果にする） |
| `estimate.js` | 先行圧縮の予想を計画に当てはめ（`withEstimate`）、予想の行・即出力の大きさ・トリミングの帯に出す |
| `fmp4.js` | 先行圧縮の書き出し（区切りごとの MP4）を読み、切り出し用に1つのファイルにまとめる |
| `fast.js` / `compat.js` | 高速モード・トリミングのみ ／ 互換モード |
| `run.js` | 圧縮の実行（`run()`：準備 → 1回ぶんの圧縮 `attempt()` → 結果かエラー）、画面スリープ防止 |
| `view.js` | 画面の出し直し、圧縮結果の表示、共有・保存 |
| `trim.js` | トリミングの部品 |
| `adjust.js` | 3ステップの画面の2択（`EASY_PRESETS`）と、2 でその動画だけ変える設定 |

決まり（`npm run lint` で一部を確かめる）:
- **読み込んだ時点で動く処理は `main.js` だけ**に置きます。ほかのモジュールは関数と値の宣言だけにします。
- **`constants.js`・`calc.js`・`fmp4.js`・`dom.js`・`state.js` はほかのモジュールを読み込みません**（`calc.js` は `constants.js` だけ）。計算を足すときは `calc.js` に置き、単体テスト（`tools/test/unit/`）も足します。
- **`export` するのは、ほかのモジュール（と単体テスト）から使うものだけ**です。
- **モジュールの変数を書き換えるのは、宣言したモジュールの中だけ**です（ほかから変えるときは、`forgetPre()` のような関数を用意する）。
- 画面の設定を足すときは、`settings.js` の `SETTING_DEFS` に1つ足せば、保存・初期値に戻す・URL に反映されます。

## プライバシー

- **動画は端末の外に送りません。** 圧縮は端末の中だけで行います（読み込めるのはこのサイトのファイルだけ：`public/_headers` の CSP）。
- ページを開くときは、ほかのWebサイトと同じく、配信元の Cloudflare が IP アドレスなどを扱います（[Cloudflare のプライバシーポリシー](https://www.cloudflare.com/privacypolicy/)）。アクセス解析や広告は入れていません。
- 設定はこの端末のブラウザ内（localStorage）に保存し、外には送りません。「現在の設定を記憶したURL」にはファイル名の自由入力の文字も入るので、人に渡すときは注意してください。
- 共有・保存と診断情報の送信は、利用者が操作したときだけです。
