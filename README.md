# アップロード不要の動画圧縮（video-compressor-under20mb）

動画をDiscordに投稿できるサイズ（20MB以下）に圧縮するサイトです。端末内の処理能力を利用して圧縮するため、アップロードは不要です。
共有シートからそのままDiscordに投稿でき、iPhoneのSafariでホーム画面に追加すればオフラインでも起動できます（PWA）。

**公開URL: https://maka-u20mb.pages.dev/**（Cloudflare Pages）

ブラウザの付属機能（WebCodecs）を利用して圧縮するため、動画がネット上にアップロードされることはありません。
ホーム画面に追加したときのアイコン名は「20MB圧縮」です。

---

## 画面

スマホの縦画面1枚にすべての操作が収まるようにしています。上から順に:

1. **元動画**（タップして動画を選択。選んだ後は再生して確認できます）
2. **トリミング**（左右の縦線のつまみで範囲を指定。つまみを動かすと、その位置の映像が表示されます。
   バーには目盛りの縦線を引いています。間隔は5秒で、長い動画は線が多くなりすぎないよう10秒・30秒…と広げます。
   元動画の再生位置は細い線でバーの上に表示し、その線を指で動かすか、バーの何もない所を触るとシークできます。
   トリミングのつまみと重なった所では、トリミングのほうが動きます。シークは圧縮後も使えます）
3. **二択の切り替え（2段）**（1つの枠の中で、選んだ側に青いつまみが付きます）
   | | 左 | 右 |
   | --- | --- | --- |
   | 上段（解像度・どちらか1つ） | 720p | 1080p |
   | 下段（圧縮方法・どちらか1つ） | なるべく圧縮 | 20MB以内に圧縮 |
4. **圧縮する**（処理中は「キャンセル」に変わり、進捗バーが出ます。目標サイズに収まらないと分かっているときは押せません）。
   圧縮が終わると「**やり直す**」に変わり、トリミングと設定は変えられなくなります。「やり直す」を押すと圧縮した動画を消して、トリミングと設定を変えられる状態に戻ります
5. **圧縮後の動画**（その場で再生して確認できます）
6. **Discord等に共有** / **保存**
   （iPhone・iPadでは「**Discord等に共有・動画保存**」の1つのボタンにまとまります。共有シートの「ビデオを保存」で写真アプリに保存できるためです）

元動画と圧縮後の動画の枠は、圧縮前は元動画を幅いっぱいに大きく（圧縮後の動画は中央の小窓）、圧縮が終わると入れ替わって圧縮後の動画を幅いっぱいに表示します
（元のままで圧縮不要のときと、圧縮し直している間は元動画が大きいままです）。

タイトルの右の「**使い方**」を押すと、説明書が開きます（画面の下端まで広がります）。
手順は、実際の画面のスクリーンショットに①〜⑤の番号と手書き風の矢印を書き込んだ画像3枚で説明し、左右にスワイプして見られます。
画像は説明書を初めて開いたときに読み込み（アプリの起動時には読みません）、一度開けばオフラインでも見られます。
4枚目は「iPhoneのショートカットを併用した使い方」のカードで、押すと別のページ（`shortcut.html`）を新しいタブで開きます。
5枚目は「Q. 無料ですか？」のカードです（検索でも読まれるよう、画像ではなく文字で書いています）。
このページ（操作の流れの画像4枚、iCloudのリンクからショートカットを取り込む方法、ショートカットの中身の画像、URLに設定を付ける方法）も、開いたときに初めて読み込みます。

「詳細設定」では、目標サイズ・下限ビットレート（720p / 1080p）・60fps→30fps・動画をアップロードしたら即圧縮・音声の有無を変えられます。
画面で変えた設定はこの端末のブラウザに保存され、次に開いたときも同じになります。ただし、URLに設定のパラメータが1つでもあるときは、前回の設定は使わず、初期値にURLの設定だけを重ねた状態で始まります（保存してある前回の設定は消しません。URLパラメータで開いたときの値は、画面で変えるまで保存しません）。「設定を初期値に戻す」で元に戻せます。

詳細設定の「**現在の設定を記憶したURLを生成してコピー**」を押すと、今の設定を下のURLパラメータにしたURLをコピーできます（既定値と同じ項目はURLから省きます）。

## なぜ作ったか

- Discordの無料アカウントのアップロード上限は現在**20MB**です（2026年8月に10MBから引き上げ。**圧縮前のファイルサイズ**で判定されます）。
  上限は今後も変わる可能性があるため、目標サイズは詳細設定やURLで変えられるようにしています（Nitro Basicの50MBなど）。
- iPhoneの「ショートカット」の*メディアをエンコード*では**ビットレートを直接指定できず**、
  解像度を段階的に下げて当たりを探すしかありません。
  このアプリは**目標サイズから逆算したビットレートを直接指定**して圧縮します。

## 想定する利用の流れ

Nintendo Switchアプリで録画した動画をDiscordに投稿するまでの流れです。

1. **Switchアプリ**の動画共有 → 共有シート → **自作のショートカット**を実行
2. ショートカットが動画を写真アプリ（またはファイルアプリ）に保存し、このWebアプリを開く
3. Webアプリで **動画を選択**（ここは手動。iOSはWeb Share Targetに非対応のため、動画を自動で受け取れません）
4. 必要ならアプリ内で**トリミング**して、**圧縮する**
5. **共有** → 共有シート → Discordに投稿

### ショートカットの作り方（概要）

ショートカットApp で新規ショートカットを作り、次のように設定します。

1. ショートカットの詳細（ⓘ）で **「共有シートに表示」をオン**にし、受け取る種類を **「メディア」** だけにする
2. （任意）アクション **「メディアをトリミング」**。アプリ内でもトリミングできるので省略してかまいません
3. アクション **「フォトアルバムに保存」**（またはファイルに保存）を追加
4. アクション **「URLを開く」** を追加し、URLに
   `https://maka-u20mb.pages.dev/?target=20&res=720` を入れる（`&auto=on` を付けると、動画を選んだらすぐ圧縮が始まります）

### URLパラメータ

画面と詳細設定のすべての項目を、URLで最初から選んでおけます。どれも省略でき、省略時は既定値になります。
手で書かなくても、詳細設定の「現在の設定を記憶したURLを生成してコピー」で作れます。

| パラメータ | 値 | 意味 | 既定 |
| --- | --- | --- | --- |
| `res` | `720` / `1080` | 出力解像度（`720p` のような表記も可） | `720` |
| `mode` | `size` / `quality` | `size`＝◯MB以内に圧縮、`quality`＝なるべく圧縮 | `size` |
| `target` | 1〜500 | 目標サイズ（MB） | `20` |
| `min720` | 100〜50000 | 720pの下限ビットレート（kbps） | `1200` |
| `min1080` | 100〜50000 | 1080pの下限ビットレート（kbps） | `2700` |
| `fps` | `30` / `source` | `30`なら60fpsの動画を30fpsにする。`source`は元のフレームレートを保つ | `30` |
| `audio` | `on` / `off` | 音声を残すか | `on` |
| `auto` | `on` / `off` | 動画を選んだらすぐ圧縮を始めるか | `off` |

`on` / `off` の代わりに `1` / `0`、`true` / `false` も使えます。範囲外や不明な値は無視して既定値になります。

例（ショートカットから、1080pで即圧縮）: `https://maka-u20mb.pages.dev/?res=1080&auto=on`

## 圧縮の方法

**解像度は選んだ720p / 1080pで固定**し（元の動画より大きくはしません）、容量は**ビットレートだけ**で調整します。

| ボタン | 映像ビットレート |
| --- | --- |
| **なるべく圧縮** | その解像度の**下限ビットレート**（既定: 720p＝1,200kbps、1080p＝2,700kbps） |
| **20MB以内に圧縮** | 下限を下回らない範囲で、**目標サイズに収まるなるべく高いビットレート** |

下限ビットレートの既定値は、720p30で1.2Mbps、1080pは画素数に比例させて同等の画質（2.7Mbps）にしています。詳細設定かURLで変えられます。

**20MB以内に圧縮**の計算:

```
映像ビットレート(bps) = 目標MB × 1,000,000 × 8 × 0.97 ÷ 秒数（トリミング後） − 音声ビットレート
```

- **1MB＝100万バイト**で数えます（iPhoneの「ファイル」アプリなどの表示と同じ）
- 目標サイズの**97%を狙います**（20MB → 19.4MB）。エンコーダの誤差（数%）を吸収して、再圧縮をなるべく避けるためです
- 上限は目標サイズそのもので、結果は**目標サイズ「未満」**に収めます（ちょうど20MBも「超えた」として扱います）
- この値が下限ビットレートを下回るときは、目標サイズに収められないので**「圧縮する」ボタンを押せなくし**、注意文を表示します
- 書き出したサイズが目標を超えたら、**実際に書き出せたサイズ**からビットレートを計算し直して、**最大2回まで自動で圧縮し直します**
  （目標サイズの97%を狙い、1回につき5%以上は下げ、下限ビットレートより下げることはありません）

共通のルール:

- 元動画の実効ビットレートの80%を超えないようにします（元より高いビットレートで焼き直しても容量が増えるだけなので）
- すでに目標サイズ以下の動画（トリミングなし）は、画質を落とさないよう**そのまま共有・保存できる状態**になります。
  さらに小さくしたい場合だけ「圧縮する」を押してください
- 「◯MB以内に圧縮」で、解像度もfpsも元のまま、トリミングした元動画が目標サイズ（の97%）に収まる見込みのときは、
  **再エンコードせずにトリミングだけ**します（画質は元のまま、数秒で終わります）。
  区切りはキーフレームに合わせるため、開始位置が指定より少し早まることがあります。
  実際に目標サイズを超えた場合は、通常の圧縮に切り替えます。
  そのときは、切り出した部分の実際のビットレートを上限にして計画し直します（ファイル全体の平均の80%で頭打ちにして、必要以上に小さくしないため）
- エンコードは可変ビットレート（VBR）を優先し（使えなければ固定ビットレート（CBR））、激しい場面に多く、静かな場面に少なく割り振ります。
  平均ビットレートは同じ計算で決めますが、仕上がりのサイズはぶれやすくなります（目標を超えたら自動で圧縮し直します）。
  どちらで圧縮したかは結果の行に「VBR」「CBR」と表示します
- iPhone・Safari（WebKit）は、CBR/VBR の指定をエンコーダに渡しません（WebKit の `WebCodecsVideoEncoder.cpp` が `bitrateMode` を使っていない）。
  そのため結果の行にも「CBR」「VBR」を表示しません。
  また、指定したビットレートの6割ほどしか使わないことがあり、目標サイズよりかなり小さく仕上がることがあります。
  目標は超えないので、そのまま使います（容量が小さいぶん送信も速くなります）

### 注意文

| 表示される条件 | 文言 |
| --- | --- |
| 予想サイズ（圧縮後は実際のサイズ）が20MBを超える | 20MBを超える為、Discord(無料垢)では送信できません。 |
| 「◯MB以内に圧縮」で目標サイズを超える | 目標サイズに圧縮できません。解像度を下げるか、詳細設定にて下限ビットレートを引き下げてください。<br>（続けて）720pなら1分56秒までなら20MBに収められます。※今の解像度・下限ビットレートでの目安 |
| 動画に位置情報（撮影場所）が入っている | 位置情報が含まれている動画です。この情報はアップロードされず、圧縮後の動画には位置情報を含めません。 |

### 位置情報などのメタデータ

書き出す動画には、元の動画の題名や日付などは残しますが、位置情報（Androidの `©xyz`、iPhoneの `com.apple.quicktime.location.ISO6709` など）を含む生のメタデータはすべて除きます。
位置情報が入っている動画は「元の動画のまま」にせず、「圧縮する」で**位置情報だけ除いて元のまま書き出します**（再圧縮なし）。トリミングのみのときも位置情報を除きます。

## 処理の仕組み

処理方式は2つあり、自動で選びます。

| | 高速モード（通常） | 互換モード（予備） |
| --- | --- | --- |
| 使う場面 | MP4 / MOV で、端末がデコードできる動画（iPhoneの撮影動画、Switchの動画など） | それ以外の動画、または高速モードが失敗したとき |
| 仕組み | [Mediabunny](https://mediabunny.dev/) の `Conversion` で動画ファイルを直接読み、`VideoDecoder` → `VideoEncoder`（WebCodecs）で変換 | `<video>` を再生しながら `requestVideoFrameCallback` でフレームを取り出し、`VideoEncoder` で圧縮して Mediabunny で mp4 にまとめる |
| 処理時間 | 端末の性能次第で**実時間より速い** | **動画の長さと同じくらい**（再生しながら取り込むため） |
| フレームレート | ファイルの実際のタイムスタンプから計算 | 冒頭を少し再生して推定 |

- 映像は H.264（avc）のハードウェアエンコードを優先し、使えない場合はHEVCを使います
- 音声は、元がAACで192kbps以下なら**再エンコードせずそのまま**使い、それ以外はAAC 128kbpsに変換します。
  変換できない端末では音声なしで書き出し、結果の行に「音声なし」と表示します
- 「60fpsの動画は30fpsにする」がオン（既定）なら、40fpsを超える動画は半分のフレームレートで書き出します
- 2秒ごとにキーフレームを入れ、出力は moov を先頭に置いた mp4（Fast Start）です
- 回転情報付きの動画（iPhoneの縦撮りなど）は、回転を映像に焼き込んで書き出します

### 共有と保存

- **共有**: `navigator.share` で共有シートを開きます。Discordへの投稿のほか、「ビデオを保存」で写真アプリにも保存できます。
  共有シートがない環境（PCなど）ではダウンロードになります。共有シートはあるのに共有を断られた場合
  （例: Androidの Chrome で .mov を元のまま共有しようとしたとき）は、ダウンロードに切り替えたうえで理由を赤字で表示します
- **保存**: `<a download>` でダウンロードします（iPhoneでは「ファイル」アプリに保存されます）

## うまく動かないとき（診断情報）

処理の経過は常に記録していて、画面のいちばん下の「**診断情報**」で見られます。
本番では普段は表示せず、エラーで終わったとき・動画を読み込めなかったとき・処理が止まったときだけ自動で開いて表示します。
ブランチのプレビューと手元の確認環境では圧縮を始めると表示し、URLに `?debug=1` を付けるとどこでも最初から表示します。
端末の種類、動画の形式、試したエンコード設定、処理の経過（10%ごとの時間）、止まった場所やエラーを記録しています。
動画の中身やファイル名は含みません。「コピー」で写して、X（[@inkaroma0431](https://x.com/inkaroma0431)）あるいはDiscordに送ってください。
画面のいちばん下にも、不具合の報告・ご要望の連絡先としてこのアカウントへのリンクを置いています。

- 画面を表示しているのに進捗が20秒止まったら、自動で互換モードに切り替えます。それでも進まなければエラーとして表示します

## 注意（重要）

- **長い動画は目標サイズに収まりません。** 下限ビットレート（既定値）と音声128kbpsのとき、収まる長さの目安は次のとおりです。

  | 目標サイズ | 720p（下限1,200kbps） | 1080p（下限2,700kbps） |
  | --- | --- | --- |
  | 20MB | 約1分56秒 | 約54秒 |
  | 50MB | 約4分52秒 | 約2分17秒 |

  これより長いときは「圧縮する」を押せません。対処: トリミングする / 720pにする / 下限ビットレートを下げる / 音声をオフにする / 目標サイズを上げる
- 下限ビットレートを下げると、長い動画でも収まる代わりに画質は大きく落ちます。
- 互換モードでは処理中に画面を開いたままにしてください（バックグラウンドに回すと止まります）。
  再圧縮が走ると、そのたびにもう一度時間がかかります（最大3回）。
- 「60fpsの動画は30fpsにする」をオフにすると、同じビットレートでも1コマあたりに使える量が半分になり、画質が下がります。
  ゲーム動画は30fpsでも見やすいので、既定はオンです。
- Discordの上限は**圧縮前のファイルサイズ**で判定されます。このアプリは1MB＝100万バイトで数え、結果を20,000,000バイト未満に収めるので、
  「20MB以内に圧縮」の結果はどちらの数え方（100万バイト / 1,048,576バイト）でも20MBに届きません。
- 本サイトは無保証で提供しています。作成者の故意または重大な過失による場合を除き、利用によって生じた損害について責任を負いません。

## 対応環境

| 環境 | 状況 |
| --- | --- |
| iOS 17以降のSafari | 対応（音声の再エンコードはiOS 17.4以降が目安） |
| iOS 16のSafari | WebCodecsの対応状況によっては動きません |
| macOS Safari 17以降 / Chrome / Edge（デスクトップ） | 対応 |
| Android の Chrome | 対応（選んだ動画は、時間が経つと読めなくなることがあるため、600MBまではすぐにブラウザ内に写し取って使います） |
| Firefox | H.264のエンコードに対応していない環境では利用できません |

必要な機能（WebCodecs の `VideoEncoder`）は起動時に判定し、非対応なら画面に表示します。
プライベートブラウズではService Workerが使えず、オフライン起動できないことがあります。

## 開発・公開

公開するのは **`public/` フォルダの中身だけ**です。静的ファイルなので、**公開時のビルドは不要**です。

```bash
# ローカルで確認（Service Workerを使うためhttpで配信する）
python3 -m http.server 8000 -d public
# → http://localhost:8000/
```

### Cloudflare Pages で公開する

**GitHub と連携する場合**（main に push するたびに自動で公開される）

1. Cloudflare のダッシュボード → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. このリポジトリを選ぶ
3. ビルドの設定
   | 項目 | 値 |
   | --- | --- |
   | Project name | 好きな名前（このリポジトリでは `maka-u20mb`） |
   | Production branch | `main` |
   | Framework preset | `None` |
   | Build command | （空欄） |
   | Build output directory | `public` |
4. **Save and Deploy** → `https://<Project name>.pages.dev/` で公開される

main 以外のブランチに push すると、そのブランチ用のプレビューURLが自動で作られます。
PRの内容を実機で試してからマージする、という使い方ができます。

**GitHub と連携しない場合**（手動でアップロード）

1. **Workers & Pages** → **Create** → **Pages** → **Upload assets**
2. `public` フォルダをドラッグ＆ドロップする（更新のたびに同じ操作をする）

パスはすべて相対パスなので、ドメイン直下（`○○.pages.dev/`）でもサブディレクトリでも、コードを変えずに動きます。

Service Worker は、本番（`maka-u20mb.pages.dev`）では**キャッシュ優先**です。キャッシュからすぐ起動し、更新は裏で取得して次に開いたときに反映します。
ブランチのプレビュー（`<ブランチ名>.maka-u20mb.pages.dev`）と手元の確認環境（localhost）では**ネット優先**です。
更新がすぐ反映され、オフラインのときや3秒以内に応答がないときだけキャッシュから起動します。どちらでもオフライン起動はできます。
動画（mp4）は Service Worker を通さずネットから直接読みます（範囲指定の読み込みに対応するため。オフラインでは再生できません）。
アセットを更新したときは `public/sw.js` の `CACHE` の値（例: `...-v5` → `...-v6`）も変えると、古いキャッシュが破棄されます。

### 同梱ライブラリの作り直し

`public/vendor/mediabunny.min.js` は、Mediabunny から**アプリが使う機能と入力形式（MP4 / MOV）だけ**を束ねたものです
（全体版は gzip 約170KB、この版は約95KB）。バージョンを上げるときなどは次で作り直します。

```bash
npm install
npm run build:vendor
```

含める機能は `tools/mediabunny-entry.js`、ビルド設定は `package.json` にあります。

### ファイル構成

| ファイル | 内容 |
| --- | --- |
| `public/index.html` | 画面とスタイル（CSSは埋め込み。フレームワークは使っていません） |
| `public/app.js` | 圧縮処理の本体 |
| `public/vendor/mediabunny.min.js` | Mediabunny の必要部分（MPL-2.0） |
| `public/sw.js` | Service Worker（本番はキャッシュ優先、プレビューはネット優先。全アセットをキャッシュしてオフラインでも起動） |
| `public/_headers` | Cloudflare Pages が付けるセキュリティ用のHTTPヘッダー（CSP など。読み込めるのはこのサイトのファイルだけ、他サイトへの埋め込みは禁止） |
| `public/manifest.json` | PWAの定義（名前「アップロード不要の動画圧縮」、ホーム画面のアイコン名「20MB圧縮」、スタンドアロン表示） |
| `public/icons/` | アイコン（PNG） |
| `public/help/` | 説明書の画像（WebP。説明書を開いたときだけ読み込む） |
| `public/shortcut.html` | iPhoneのショートカットを併用した使い方のページ（説明書のカードから開く。画像は `public/help/sc-*.webp`） |
| `package.json` / `tools/` | 同梱ライブラリを作り直すときだけ使う設定（公開はされない） |
