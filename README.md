# アップロード不要の動画圧縮（video-compressor-under20mb）

動画をDiscordに投稿できるサイズ（20MB以下）に圧縮するサイトです。端末内の処理能力を利用して圧縮するため、アップロードは不要です。
共有シートからそのままDiscordに投稿でき、iPhoneのSafariでホーム画面に追加すればオフラインでも起動できます（PWA）。

**公開URL: https://maka-u20mb.pages.dev/**（Cloudflare Pages）

ブラウザの付属機能（WebCodecs）を利用して圧縮するため、動画がネット上にアップロードされることはありません。
ホーム画面に追加したときのアイコン名は「20MB圧縮」です。

---

## 画面

アプリの画面（`https://maka-u20mb.pages.dev/`、`index.html`）は、3ステップで圧縮します。
すべての部品を1つの画面に並べた**従来の画面**も `https://maka-u20mb.pages.dev/old`（`old.html`）に残しています。
アプリの画面の下の「従来の画面」と、従来の画面の見出しの「新しい画面」で行き来できます（従来の画面では、動画を選んだあとは見出しに「別の動画」を出すので「新しい画面」は隠します）。
見出しの「使い方」で説明書を開けます（アプリの画面は手順の画像4枚、従来の画面は3枚。ショートカットのページ・よくある質問・更新情報は共通の内容）。
開発ブランチのプレビュー（`<ブランチ名>.maka-u20mb.pages.dev`）では、見出しにサイト名の代わりに版（例: `ver 2026-10-01e`）を出します（本番は出しません）。

### アプリの画面（3ステップ）

1. **圧縮の仕方を選ぶ**（大きな2択と「詳しく設定する」）
   - **なるべく圧縮**：720p・30fps・指定ビットレートは初期値（1,200kbps）
   - **画質優先（20MB以内）**：元の画質とfpsのまま、20MBに収まるなるべく高いビットレート（指定ビットレートは初期値の2,700kbpsを下回らない）
   - **詳しく設定する**：1 と 2 の間に「設定」のステップを足し、従来の画面と同じ設定（解像度・圧縮方法・詳細設定を開いたもの）を出す。
     設定は従来の画面と共通で、保存してある設定を使い、変えたら保存する。手順の帯も「選ぶ・設定・動画・保存」の4つにする
2. **動画を選んでトリミング**：プレビュー・トリミング・予想を出し、「圧縮する」を目立たせる。
   トリミングの下で、**その動画だけ**解像度・fps・圧縮方法を変えられる（設定のステップと同じ見た目。動画を選ぶまでは出さない）。
   新しい動画を選ぶ・圧縮の仕方を選び直す・設定のステップで設定を変えると元に戻る（保存しない）
   - 解像度：480p・720p・1080p（元の動画より大きい解像度は選べない。縦横比はそのまま、短い辺を480にする。480pの指定ビットレートは720pの値を画素数に比例させる（初期値で約533kbps））
   - fps：30fps・60fps（60fpsなどの動画のときだけ選べる）
   - 圧縮方法：なるべく圧縮（指定ビットレート）・◯MB以内に圧縮（目標サイズに収まるなるべく高いビットレート）
   予圧縮は、変えた設定でやり直す。予圧縮は従来の画面と同じで、押せばすぐ出せるときは「◯MBで即出力するよ」を出す（画質優先では、予圧縮が20MBの95〜100%ならそのまま使う）。20MB以下の動画は「圧縮せずに、このまま共有・保存へ」で進める
3. **共有・保存**：進み具合と仕上がりを出し、「Discord等に共有」「保存」を大きく出す。「範囲を変えてやり直す」「別の動画を圧縮する」で戻れる

- 上の手順の帯で前のステップに戻れます（圧縮中は戻れません。キャンセルすると 2 に戻ります）。
- 2 は、どれを選んでも動画とトリミングだけです。「別の動画」で動画を選び直せ、「変更」で 1（「詳しく設定する」なら設定のステップ）に戻れます。
- 2択のときは、この端末に保存してある設定は使わず、2択で決めた設定も保存しません。
- **720p・1080p ではない動画**（スマホの画面録画・4K・小さい動画など）は、どれを選んでも元の解像度のまま圧縮し、2 に「720p・1080pではない動画のため、そのままの解像度（幅×高さ）で圧縮します。」と出します。2 の解像度は出さず、設定のステップの解像度も押せません。
- **URLに設定のパラメータがあるとき**（ショートカットから開いたときなど）は、その設定の「詳しく設定する」にして、すぐ 2 から始めます（保存してある設定の代わりにURLの設定を使う。従来の画面と同じ）。`auto=on` なら、動画を選んだらそのまま圧縮して 3 に進みます
- 圧縮の処理は従来の画面と同じ `app.js` です。`index.html` に同じ id の部品を置き（body に `easy`）、ステップの切り替えは `easy.js` が行います。

### 従来の画面（`/old`）

スマホの縦画面1枚にすべての操作が収まるようにしています。上から順に:

1. **元動画**（タップして動画を選択。選んだ後は再生して確認できます）
2. **トリミング**（左右の縦線のつまみで範囲を指定。つまみを動かすと、その位置の映像が表示されます。
   バーには目盛りの縦線を引いています。間隔は5秒で、長い動画は線が多くなりすぎないよう10秒・30秒…と広げます。
   元動画の再生位置は細い線でバーの上に表示し、その線を指で動かすか、バーの何もない所を触るとシークできます。
   トリミングのつまみと重なった所では、トリミングのほうが動きます。シークは圧縮後も使えます）
3. **二択の切り替え（2段）**（1つの枠の中で、選んだ側に青いつまみが付きます）
   | | 左 | 右 |
   | --- | --- | --- |
   | 上段（解像度・どちらか1つ） | 720p | 1080p |
   | 下段（圧縮方法・どちらか1つ） | なるべく圧縮 | 20MB以内に圧縮 |

   スマホの画面録画など、720p・1080p 以外で720pより大きい動画（短い辺が728pxより大きく、1080から±8pxより離れているもの）を選んだときは、
   上段の右に「**元の解像度**」が増えて三択になります。選ぶと解像度を変えずに圧縮します。
   選んだことは覚えていて、720p・1080p の動画のあいだは 1080p になり、次にそれ以外の動画を選ぶと「元の解像度」に戻ります
4. **圧縮する**（処理中は「キャンセル」に変わり、進捗バーが出ます。目標サイズに収まらないと分かっているときは押せません）。
   圧縮が終わると「**やり直す**」に変わり、トリミングと設定は変えられなくなります。「やり直す」を押すと圧縮した動画を消して、トリミングと設定を変えられる状態に戻ります
5. **圧縮後の動画**（その場で再生して確認できます）
6. **Discord等に共有** / **保存**
   （iPhone・iPadでは「**Discord等に共有・動画保存**」の1つのボタンにまとまります。共有シートの「ビデオを保存」で写真アプリに保存できるためです）

元動画と圧縮後の動画の枠は、圧縮前は元動画を幅いっぱいに大きく（圧縮後の動画は中央の小窓）、圧縮が終わると入れ替わって圧縮後の動画を幅いっぱいに表示します
（元のままで圧縮不要のときと、圧縮し直している間は元動画が大きいままです）。

タイトルの右の「**使い方**」を押すと、説明書が開きます（画面の下端まで広がります）。
手順は、実際の画面のスクリーンショットに①〜⑤の番号と手書き風の矢印を書き込んだ画像3枚で説明し、左右にスワイプして見られます。
画像は説明書を初めて開いたときに読み込み（アプリの起動時には読みません）、一度開けばオフラインでも見られます。
4枚目は「iPhoneのショートカットを併用した使い方」のカードで、押すと別のページ（`shortcut.html`）を新しいタブで開きます。
5〜15枚目はよくある質問のカードです（無料か・動画や個人情報は送られるか・広めてもいいか・対応スマホ・他のWeb圧縮サイトとの違い・対応するファイル形式・iPhoneの60fps・HDRの動画・20MBに入る長さ・圧縮中に他のアプリを開いてよいか・ホーム画面に追加・うまく動かないとき）。
16枚目（最後）は「更新情報」のカードで、日付と変更内容を新しいものから順に書きます（2026年9月28日：サイト公開）。検索でも読まれるよう、画像ではなく文字で書いています。
このページ（操作の流れの画像4枚、iCloudのリンクからショートカットを取り込む方法、ショートカットの中身の画像、URLに設定を付ける方法）も、開いたときに初めて読み込みます。

「詳細設定」では、目標サイズ・指定ビットレート（720p / 1080p）・60fps→30fps・動画を選んだらすぐ圧縮・音声の有無・書き出す動画のファイル名を変えられます。

**ファイル名の指定**（既定はオフ）：オンにすると、次の項目から使うものを選び、↑↓で並べた順に「_」でつないだ名前にします（例: `20260926153012_クリップ_720p-20MB_k7mq.mp4`）。

| 項目 | 入る文字 |
| --- | --- |
| 日付 / 日付+時間 | 圧縮した日時（`20260926` / `20260926153012`＝年月日時分秒）。どちらか1つだけ選べます |
| 自由入力 / 自由入力2 | 入力した文字（文字と数字、「-」「_」だけ。絵文字・記号・空白は外し、10文字まで。空なら飛ばす） |
| ランダム英数字4桁 | 小文字の英字と数字4文字（例: `k7mq`。見間違えやすい 0・o・1・l・i は使わない） |
| 圧縮オプション | `720p-20MB`・`1080p-なるべく`・`元解像度-20MB` など。トリミングのみは `トリミング`、元のまま渡すときは `元のまま` |
| 元のファイル名 | 選んだ動画の名前（拡張子なし） |

既定では「日付」「自由入力」「圧縮オプション」にチェックが入っています。全部オフのときは今までの名前（`元の名前_compressed.mp4` など）になります。
圧縮不要で元の動画をそのまま渡すときも同じ名前を付けます（拡張子は元のまま）。
画面で変えた設定はこの端末のブラウザに保存され、次に開いたときも同じになります。ただし、URLに設定のパラメータが1つでもあるときは、前回の設定は使わず、初期値にURLの設定だけを重ねた状態で始まります（保存してある前回の設定は消しません。URLパラメータで開いたときの値は、画面で変えるまで保存しません）。「設定を初期値に戻す」で元に戻せます。

詳細設定の「**現在の設定を記憶したURLを生成してコピー**」を押すと、今の設定を下のURLパラメータにしたURLをコピーできます（既定値と同じ項目はURLから省きます）。

## なぜ作ったか

- Discordの無料アカウントのアップロード上限は現在**20MB**です（2026年8月に10MBから引き上げ。**圧縮前のファイルサイズ**で判定されます）。
  上限は今後も変わる可能性があるため、目標サイズは詳細設定やURLで変えられるようにしています（Nitro Basicの50MBなど）。
- iPhoneの「ショートカット」の*メディアをエンコード*では**ビットレートを直接指定できず**、
  解像度を段階的に下げて当たりを探すしかありません。
  このアプリは**目標サイズから逆算したビットレートを直接指定**して圧縮します。

## 想定する利用の流れ

Nintendo Switchアプリで録画した動画をDiscordに投稿するまでの流れです。

1. **Switchアプリ**の動画共有 → 共有シート → **自作のショートカット**を実行
2. ショートカットが動画を写真アプリ（またはファイルアプリ）に保存し、このWebアプリを開く
3. Webアプリで **動画を選択**（ここは手動。iOSはWeb Share Targetに非対応のため、動画を自動で受け取れません）
4. 必要ならアプリ内で**トリミング**して、**圧縮する**
5. **共有** → 共有シート → Discordに投稿

### ショートカットの作り方（概要）

ショートカットApp で新規ショートカットを作り、次のように設定します。

1. ショートカットの詳細（ⓘ）で **「共有シートに表示」をオン**にし、受け取る種類を **「メディア」** だけにする
2. （任意）アクション **「メディアをトリミング」**。アプリ内でもトリミングできるので省略してかまいません
3. アクション **「フォトアルバムに保存」**（またはファイルに保存）を追加
4. アクション **「URLを開く」** を追加し、URLに
   `https://maka-u20mb.pages.dev/?target=20&res=720` を入れる（`&auto=on` を付けると、動画を選んだらすぐ圧縮が始まります）

### URLパラメータ

画面と詳細設定のすべての項目を、URLで最初から選んでおけます。どれも省略でき、省略時は既定値になります。
手で書かなくても、詳細設定の「現在の設定を記憶したURLを生成してコピー」で作れます。

| パラメータ | 値 | 意味 | 既定 |
| --- | --- | --- | --- |
| `res` | `720` / `1080` / `source` | 出力解像度（`720p` のような表記も可）。`source`（`original` も可）は元の解像度のまま（720p・1080p 以外で720pより大きい動画のときだけ使われ、それ以外の動画では 1080p） | `720` |
| `mode` | `size` / `quality` | `size`＝◯MB以内に圧縮、`quality`＝なるべく圧縮 | `size` |
| `target` | 1〜500 | 目標サイズ（MB） | `20` |
| `min720` | 100〜50000 | 720pの指定ビットレート（kbps） | `1200` |
| `min1080` | 100〜50000 | 1080pの指定ビットレート（kbps） | `2700` |
| `fps` | `30` / `source` | `30`なら60fpsの動画を30fpsにする。`source`は元のフレームレートを保つ | `30` |
| `audio` | `on` / `off` | 音声を残すか | `on` |
| `auto` | `on` / `off` | 動画を選んだらすぐ圧縮を始めるか | `off` |
| `name` | `date,text1,opt` など / `off` | ファイル名を指定する（使う項目を並べる順にカンマで区切る。`date`・`datetime`・`text1`・`text2`・`rand`・`opt`・`orig`）。`off` で指定しない | 指定しない |
| `text1` / `text2` | 文字 | ファイル名の自由入力 / 自由入力2 | 空 |

`on` / `off` の代わりに `1` / `0`、`true` / `false` も使えます。範囲外や不明な値は無視して既定値になります。

例（ショートカットから、1080pで即圧縮）: `https://maka-u20mb.pages.dev/?res=1080&auto=on`

## 圧縮の方法

**解像度は選んだ720p / 1080p（または元の解像度）で固定**し（元の動画より大きくはしません）、容量は**ビットレートだけ**で調整します。
720p以下の動画（短い辺が720付近以下）では、720pにして1080pを選べなくします（選んでいた1080pは覚えておき、大きい動画を選んだら戻します）。
「元の解像度」の指定ビットレートは、720pの値を画素数に比例させた値です（例: 886×1920 なら約2.2Mbps）。
60fpsのまま書き出すときは、指定ビットレートを1.5倍にします（指定ビットレートは30fpsを前提にした値。例: 1080p60 は4.05Mbps）。

| ボタン | 映像ビットレート |
| --- | --- |
| **なるべく圧縮** | その解像度の**指定ビットレート**（既定: 720p＝1,200kbps、1080p＝2,700kbps） |
| **20MB以内に圧縮** | 指定ビットレートを下回らない範囲で、**目標サイズに収まるなるべく高いビットレート** |

指定ビットレートの既定値は、720p30で1.2Mbps、1080pは画素数に比例させて同等の画質（2.7Mbps）にしています。詳細設定かURLで変えられます。

**20MB以内に圧縮**の計算:

```
映像ビットレート(bps) = 目標MB × 1,000,000 × 8 × 0.97 ÷ 秒数（トリミング後） − 音声ビットレート
```

- **1MB＝100万バイト**で数えます（iPhoneの「ファイル」アプリなどの表示と同じ）
- 目標サイズの**97%を狙います**（20MB → 19.4MB）。エンコーダの誤差（数%）を吸収して、再圧縮をなるべく避けるためです
- 上限は目標サイズそのもので、結果は**目標サイズ「未満」**に収めます（ちょうど20MBも「超えた」として扱います）
- この値が指定ビットレートを下回るときは、目標サイズに収められないので**「圧縮する」ボタンを押せなくし**、注意文を表示します
  （ただし、元動画のビットレートがもともと指定ビットレートより低い動画には、指定ビットレートは当てはめません。その動画では設定で選べる最小値（100kbps）にし、
  初回の計画・圧縮し直し・「◯分まで収まる」の目安で同じ値を使います）
- 書き出したサイズが目標を超えたら、**実際に書き出せたサイズ**からビットレートを計算し直して、**最大2回まで自動で圧縮し直します**
  （目標サイズの97%を狙い、1回につき5%以上は下げ、指定ビットレートより下げることはありません）

共通のルール:

- 元動画の実効ビットレート（元が HEVC なら1.5倍）を超えないようにします（元より高いビットレートで焼き直しても容量が増えるだけなので。
  HEVC は、書き出す H.264 で同じ画質にするのに約1.5倍のビットレートが要ります）
- すでに目標サイズ以下の動画（トリミングなし）は、画質を落とさないよう**そのまま共有・保存できる状態**になります
  （位置情報が入っている・入っているか分からないとき、「音声を残す」がオフで音声が入っているときを除く。このときは取り除いて書き出す）。
  さらに小さくしたい場合だけ「圧縮する」を押してください
- 「◯MB以内に圧縮」で、解像度もfpsも元のまま、トリミングした元動画が目標サイズ（の97%）に収まる見込みのときは、
  **再エンコードせずにトリミングだけ**します（画質は元のまま、数秒で終わります）。
  再エンコードしない切り出しはキーフレームからしか始められないため、ファイルには範囲の始まりより前（直前のキーフレームから）も入りますが、
  その部分は MP4 のエディットリストで再生しないようにしているので、再生される始まりと長さは範囲どおりです
  （エディットリストに対応していないプレイヤーでは、その部分も見えることがあります）。
  実際に目標サイズを超えた場合は、通常の圧縮に切り替えます。
  そのときは、切り出した部分の実際のビットレートを上限にして計画し直します（ファイル全体の平均で頭打ちにして、必要以上に小さくしないため）
- エンコードは可変ビットレート（VBR）で、激しい場面に多く、静かな場面に少なく割り振ります。
  エンコーダーは、ハードウェアの VBR → （ハードウェアの VBR が使えないときだけ）ハードウェアの固定ビットレート（CBR）→
  ソフトウェアの VBR の順に選びます（互換モードも同じ）。どちらで圧縮したかは結果の行に「VBR」「CBR」と表示します
- VBR では指定のビットレートを守らないエンコーダーがあります（Android の実機で、指定ビットレート 1.2Mbps が 2.4〜2.9Mbps になり、
  ビットレートを下げても小さくならなかった）。そのときも CBR で圧縮し直すことはしません。
  サイズは、予圧縮で実際に書き出した量から予想し、目標に収まる長さの目安を押す前に出します。
  「◯MB以内」で目標を超えたときはビットレートを下げて圧縮し直しますが、前回より3%以上小さくならなければ、そこでやめます（前回の方が小さければ前回の結果を使います）。
  指定ビットレートを下げて予圧縮をやり直しても、前回より3%以上小さくならないときも同じで、どちらも「この端末ではこれ以上ビットレートを下げられないみたいです。」と出します
- 元の音声をそのままコピーして失敗したとき（音声の設定データが壊れた動画など）は、互換モードにせず、
  音声を AAC に作り直して（読めない・AAC で書き出せないときは音声を外して）高速モードのままやり直します
- iPhone・Safari（WebKit）は、CBR/VBR の指定をエンコーダに渡しません（WebKit の `WebCodecsVideoEncoder.cpp` が `bitrateMode` を使っていない）。
  そのため結果の行にも「CBR」「VBR」を表示しません。
  また、指定したビットレートの6割ほどしか使わないことがあり、目標サイズよりかなり小さく仕上がることがあります。
  目標は超えないので、そのまま使います（容量が小さいぶん送信も速くなります）

### 予圧縮（サイズの予想と即出力）

エンコーダーは、映像によって指定のビットレートを守りません（重い映像では下げきれずに多く使い、軽い映像では使い切りません。
iPhone の 1080p60 のゲーム映像で、2.7Mbps・4.05Mbps のどちらを指定しても約7.5Mbps になりました）。そこで、実際に圧縮して測ります。

- 動画を読み込んだら（解像度・fps・音声などの設定を変えたときも）、**範囲に関係なく動画の最初から最後まで**を、
  **指定ビットレート**で裏で圧縮します（予圧縮）。設定を変えたら止めて、1.5秒後にやり直します。範囲を変えただけならやり直しません。
  画面を離れたら止め、戻ったら最初からやり直します。「動画を選んだらすぐ圧縮」がオンのとき・互換モードのときはしません
- 書き出しは区切り（fragmented MP4。キーフレームごと＝約2秒ごと）ごとに受け取り、区切りの表から1コマごとの大きさ・時刻を読みます
- 予想の行は、予圧縮が進むと実測に置き換わります（`→ 1920×1080・30fps・7.3Mbps・予想19.8 MB（予圧縮 35%）`、次の行に `約20秒まで20MBに収まるよ`）
  - ビットレートは予想のサイズから求めた値。**なるべく圧縮**の予想は、範囲の終わりまで済んでいれば切り出す範囲のコマを足した値
    （テストの動画で誤差0.01〜0.03%）、済んでいなければ済んだ所の平均で見込んだ値
  - **20MB以内**の予想は、区切りごとに「指定」と「指定ビットレートでの実測」の大きい方を、狙うサイズ（目標の97%）で頭打ちにした値
    （エンコーダーは平均を指定に寄せるので、大きい方をとる見込みは多めに出る）
  - 次の行には、指定ビットレートでの実測の平均で目標サイズに収まる秒数の95%を出す。範囲がそれより長いときは
    「20MBに収めるなら約20秒以内にトリミングしてね」にし、トリミングの帯を黄色にする
    （ただし、切り出した大きさが正確に分かっていて目標未満なら、長くても「20MBに収まるよ」にし、黄色にしない）
- 予圧縮が済んだら、「なるべく圧縮」の下に「◯MBで即出力するよ」を出します。
  「20MB以内に圧縮」でも、切り出した大きさが目標の95%以上・目標未満なら、同じく下に出して予圧縮を使います
  （このときは、指定ビットレートの計算では収まらない場合でも「圧縮する」を押せます。軽い映像ではエンコーダーが指定ビットレートちょうどに収めるため）
- 設定を変えずに「圧縮する」を押したら、予圧縮が範囲の始まりまで届いていれば、範囲の終わりまで続けてから止め、範囲を切り出して結果にします
  （再エンコードなし。ファイルには範囲の始まりより最大2秒前のキーフレームから入るが、その部分は再生されないので、再生される始まりと長さは範囲どおり）。
  届いていなければ止めて、範囲だけを普通に圧縮します。
  切り出せなかったとき・切り出した動画が短かったときも、普通の圧縮に切り替えます
- VBR の指定を守らない端末でも、予圧縮は VBR のまま行い、実際に書き出した量を予想にし、押したらそのまま切り出します
- 結果の行のビットレートは、書き出した大きさと長さから求めた実際の値（指定と1割以上違えば「5.7Mbps（指定3.0Mbps）」）です
- 「20MB以内に圧縮」で目標の8割以下に仕上がったら、「これ以上大きくしても画質はほぼ上がらないため、15.9MBに抑えました。」と出します

| 動画を読み込めない（壊れている・動画でない） | 動画を読み込めませんでした。一時的に読み込めないこともあるので、まずは「動画を選択」からもう一度選び直してください。何度選んでも読み込めないときは、ファイルが壊れているか、対応していない形式です（MP4・MOVに対応しています）。 |
| 動画に位置情報（撮影場所）が入っている | 位置情報が含まれている動画です。この情報はアップロードされず、圧縮後の動画には位置情報を含めません。 |

### 位置情報などのメタデータ

書き出す動画には、元の動画の題名や日付などは残しますが、位置情報（Androidの `©xyz`、iPhoneの `com.apple.quicktime.location.ISO6709` など）を含む生のメタデータはすべて除きます。
位置情報が入っている動画は「元の動画のまま」にせず、「圧縮する」で**位置情報を除いて元のまま書き出します**（再圧縮なし）。トリミングのみのときも位置情報を除きます。
位置情報が入っているか**分からない**とき（メタデータを読めなかった、互換モードで読み込んだ動画など）も、入っているものとして扱い、元の動画はそのまま渡しません
（互換モードでは再エンコードするので、メタデータは残りません）。高速モードで分かった有無は、互換モードに切り替わっても引き継ぎます。

「音声を残す」がオフで、元の動画に音声が入っている（または入っているか分からない）ときも、元の動画はそのまま渡さず、**音声を除いて元のまま書き出します**（再圧縮なし。互換モードでは再エンコード）。

## 処理の仕組み

処理方式は2つあり、自動で選びます。

| | 高速モード（通常） | 互換モード（予備） |
| --- | --- | --- |
| 使う場面 | MP4 / MOV で、端末がデコードできる動画（iPhoneの撮影動画、Switchの動画など） | それ以外の動画、または高速モードが失敗したとき |
| 仕組み | [Mediabunny](https://mediabunny.dev/) の `Conversion` で動画ファイルを直接読み、`VideoDecoder` → `VideoEncoder`（WebCodecs）で変換 | `<video>` を再生しながら `requestVideoFrameCallback` でフレームを取り出し、`VideoEncoder` で圧縮して Mediabunny で mp4 にまとめる |
| 処理時間 | 端末の性能次第で**実時間より速い** | **動画の長さと同じくらい**（再生しながら取り込むため） |
| フレームレート | ファイルの実際のタイムスタンプから計算 | 冒頭を少し再生して推定 |

- 映像は H.264（avc）のハードウェアエンコードを優先し、使えない場合はHEVCを使います
- 音声は、元がAACで192kbps以下なら**再エンコードせずそのまま**使い、それ以外はAAC 128kbpsに変換します。
  変換できない端末では音声なしで書き出し、結果の行に「音声なし」と表示します
- 「60fpsの動画は30fpsにする」がオン（既定）なら、40fpsを超える動画は半分のフレームレートで書き出します
- 2秒ごとにキーフレームを入れ、出力は moov を先頭に置いた mp4（Fast Start）です
- 回転情報付きの動画（iPhoneの縦撮りなど）は、回転を映像に焼き込んで書き出します

### 共有と保存

- **共有**: `navigator.share` で共有シートを開きます。Discordへの投稿のほか、「ビデオを保存」で写真アプリにも保存できます。
  共有シートがない環境（PCなど）ではダウンロードになります。共有シートはあるのに共有を断られた場合
  （例: Androidの Chrome で .mov を元のまま共有しようとしたとき）は、ダウンロードに切り替えたうえで理由を赤字で表示します
- **保存**: `<a download>` でダウンロードします（iPhoneでは「ファイル」アプリに保存されます）

## うまく動かないとき（診断情報）

処理の経過は常に記録していて、画面のいちばん下の「**診断情報**」で見られます。
本番では普段は表示せず、エラーで終わったとき・動画を読み込めなかったとき・処理が止まったときだけ自動で開いて表示します。
ブランチのプレビューと手元の確認環境では圧縮を始めると表示し、URLに `?debug=1` を付けるとどこでも最初から表示します。
端末の種類、動画の形式、試したエンコード設定、処理の経過（10%ごとの時間）、止まった場所やエラーを記録しています。
動画の中身やファイル名は含みません。「コピー」で写して、X（[@inkaroma0431](https://x.com/inkaroma0431)）あるいはDiscordに送ってください。
画面のいちばん下にも、不具合の報告・ご要望の連絡先としてこのアカウントへのリンクを置いています。

- 画面を表示しているのに進捗が20秒止まったら、自動で互換モードに切り替えます。それでも進まなければエラーとして表示します

## 注意（重要）

- **長い動画は目標サイズに収まりません。** 指定ビットレート（既定値）と音声128kbpsのとき、収まる長さの目安は次のとおりです。

  | 目標サイズ | 720p（指定1,200kbps） | 1080p（指定2,700kbps） |
  | --- | --- | --- |
  | 20MB | 約1分56秒 | 約54秒 |
  | 50MB | 約4分52秒 | 約2分17秒 |

  これより長いときは「圧縮する」を押せません。対処: トリミングする / 720pにする / 指定ビットレートを下げる / 音声をオフにする / 目標サイズを上げる
- 指定ビットレートを下げると、長い動画でも収まる代わりに画質は大きく落ちます。
- 圧縮中は画面を開いたままにしてください。別のアプリに切り替えると、iPhone では動画の読み込み・書き出しが壊れたり止まったりします（`EncodingError: Decoder failure` など）。
  そのときは動画のせいではないので互換モードには切り替えず、画面に戻るのを待ってから同じ方式で最初からやり直します（最大3回。戻ってから3秒進まないときも同じ）。
  iPhone では、切り替えると動画のデコーダーが固まり、Safari を開き直すまで直らないことがあります。戻ったとき・圧縮を始めるとき・動画を選んだときに、デコーダーが2秒応答しなければ固まったとみなし、互換モードは試さずに開き直すよう案内します（固まると高速モードも互換モードも進みません）。
  切り替え始めた瞬間に失敗し、画面が隠れた知らせはその直後に届くので、失敗してから1.5秒待って見極めます。知らせが届かないこともあるため、ページが3秒以上止められていたことでも見分けます。
  別のアプリに切り替えると画面を暗くしない設定（Wake Lock）が外れるので、戻ったときに圧縮中なら取り直します。
- 互換モードでは処理中に画面を開いたままにしてください（バックグラウンドに回すと止まります）。
  iPhone の低電力モードでは、互換モードで使う動画の再生が許可されないことがあります（そのときは低電力モードをオフにするよう案内します）。
  再圧縮が走ると、そのたびにもう一度時間がかかります（最大3回）。
- 「60fpsの動画は30fpsにする」をオフにすると、同じビットレートでも1コマあたりに使える量が半分になり、画質が下がります。
  ゲーム動画は30fpsでも見やすいので、既定はオンです。
- Discordの上限は**圧縮前のファイルサイズ**で判定されます。このアプリは1MB＝100万バイトで数え、結果を20,000,000バイト未満に収めるので、
  「20MB以内に圧縮」の結果はどちらの数え方（100万バイト / 1,048,576バイト）でも20MBに届きません。
- **iPhoneで写真アプリから選ぶと、iOSが動画を変換してから渡します**（ブラウザに届く前に、HEVC→H.264・HDRなし・30fpsになる。長い動画ほど変換に時間がかかる）。
  そのため「元の動画のまま」で渡しても、中身は変換後の動画です。
  60fpsのまま使うには、写真アプリの共有から「"ファイル"に保存」し、「動画を選択」→「ファイルを選択」から選びます（元の HEVC・HDR・60fps のまま届く。圧縮すると H.264・HDRなしになる）。
  このときは詳細設定の「60fpsの動画は30fpsにする」もオフにします。
- Android で、Googleフォトの端末に保存されていない（クラウドだけの）大きい動画を選ぶと、ダウンロードが終わらず、選んでも何も起きないことがあります
  （ブラウザに動画が届かないため、アプリからは検知できない）。先にGoogleフォトで端末に保存してから選んでください。
- iPhoneの動画には、空間オーディオ（APAC）など読めない音声が AAC と一緒に入っていることがあります。読めない方は外し、AAC の音声を使います。
- 本サイトは現状のまま無保証で提供しており、動作や圧縮結果を保証するものではありません。

## 対応環境

| 環境 | 状況 |
| --- | --- |
| iPhone（iOS 16.4以降。iPhone 8以降） | 対応（Safari 以外のブラウザも中身は同じ WebKit なので同じ）。音声の変換（AudioEncoder）は iOS 26 以降。それより前は元の音声が AAC ならそのまま使い、AAC 以外は音声なし |
| macOS Safari 16.4以降 / Chrome / Edge（デスクトップ） | 対応 |
| Android の Chrome | Android 10 以降（最新の Chrome）で対応。WebCodecs は Chrome 94 から使えるが、Chrome 139 以降は Android 10 以上が必要（Android 8・9 は Chrome 138 で更新終了・未確認）。選んだ動画は、時間が経つと読めなくなることがあるため、600MBまではすぐにブラウザ内に写し取って使います |
| Firefox | Android 版は VideoEncoder に非対応のため利用できません（デスクトップ版は 130 以降で WebCodecs に対応） |

必要な機能（WebCodecs の `VideoEncoder`）は起動時に判定し、非対応なら画面に表示します。
プライベートブラウズではService Workerが使えず、オフライン起動できないことがあります。

## 開発・公開

公開するのは **`public/` フォルダの中身だけ**です。静的ファイルなので、**公開時のビルドは不要**です。

```bash
# ローカルで確認（Service Workerを使うためhttpで配信する）
python3 -m http.server 8000 -d public
# → http://localhost:8000/
```

### Cloudflare Pages で公開する

**GitHub と連携する場合**（main に push するたびに自動で公開される）

1. Cloudflare のダッシュボード → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. このリポジトリを選ぶ
3. ビルドの設定
   | 項目 | 値 |
   | --- | --- |
   | Project name | 好きな名前（このリポジトリでは `maka-u20mb`） |
   | Production branch | `main` |
   | Framework preset | `None` |
   | Build command | （空欄） |
   | Build output directory | `public` |
4. **Save and Deploy** → `https://<Project name>.pages.dev/` で公開される

main 以外のブランチに push すると、そのブランチ用のプレビューURLが自動で作られます。
PRの内容を実機で試してからマージする、という使い方ができます。

**GitHub と連携しない場合**（手動でアップロード）

1. **Workers & Pages** → **Create** → **Pages** → **Upload assets**
2. `public` フォルダをドラッグ＆ドロップする（更新のたびに同じ操作をする）

パスはすべて相対パスなので、ドメイン直下（`○○.pages.dev/`）でもサブディレクトリでも、コードを変えずに動きます。

Service Worker は、本番（`maka-u20mb.pages.dev`）では**キャッシュ優先**です。キャッシュからすぐ起動し、更新は裏で取得して次に開いたときに反映します。
裏で取得したものをキャッシュに保存し終わるまで、Service Worker を止めないようにブラウザに伝えています（`waitUntil`）。保存に失敗しても（容量不足など）、画面の表示は失敗させません。
ブランチのプレビュー（`<ブランチ名>.maka-u20mb.pages.dev`）と手元の確認環境（localhost）では**ネット優先**です。
更新がすぐ反映され、オフラインのときや3秒以内に応答がないときだけキャッシュから起動します。どちらでもオフライン起動はできます。
動画（mp4）は Service Worker を通さずネットから直接読みます（範囲指定の読み込みに対応するため。オフラインでは再生できません）。
`public/` のファイルを変えたときは、コミットの前に `npm run bump` を実行して版を上げます
（`public/sw.js` のキャッシュ名 `...-v100` → `...-v101` と、診断情報に出す `public/app.js` の `APP_VERSION` を一度に上げます）。
キャッシュ名を上げないと古いキャッシュが破棄されず、利用者は前の版のままになります。

### 同梱ライブラリの作り直し

`public/vendor/mediabunny.min.js` は、Mediabunny から**アプリが使う機能と入力形式（MP4 / MOV）だけ**を束ねたものです
（全体版は gzip 約170KB、この版は約95KB）。バージョンを上げるときなどは次で作り直します。

```bash
npm install
npm run build:vendor
```

含める機能は `tools/mediabunny-entry.js`、ビルド設定は `package.json` にあります。

### テスト

実際のブラウザでアプリを動かし、動画を圧縮して結果を確かめるテストがあります（`tools/test/`。[Playwright](https://playwright.dev/) を使用）。
予圧縮は、`probe.spec.js` 以外では URL の `probe=off` で止めています（本番の圧縮だけを確かめるため。自己テストのページも「予圧縮を試す」以外は同じ）。
コードを直したら、公開する前に実行してください。

必要なもの：Node.js、ffmpeg（テスト用の動画を作る）、H.264 と AAC を扱える Chrome（パソコンの Google Chrome など。オープンソース版の Chromium では動きません）

```sh
npm install
npm run test:videos   # テスト用の動画を tools/test/videos/ に作る（最初の1回だけ。約2分・約470MB。名前に大きさが入った動画は、その大きさで作れたかも確かめる）
npm test              # すべてのテストを実行（約15分）
npm test -- strip.spec.js   # 一部だけ実行するとき
```

| 環境変数 | 内容 |
| --- | --- |
| `FFMPEG` | ffmpeg の場所（既定は PATH の `ffmpeg`） |
| `CHROME_PATH` | 使う Chrome の実行ファイル（既定はインストールした Google Chrome） |
| `CHROME_ARGS` | Chrome に足す引数（GPU のない Linux では `--disable-gpu` を付けると縮小が速い） |
| `WORKERS` | 同時に動かすテストの数（既定は1。変換が重いため） |

| ファイル | 確かめること |
| --- | --- |
| `matrix.spec.js` | 端末（PC・Android・iPhone の画面）× 動画（720p・1080p・縦長・回転情報つき・画面録画）で、20MB未満・正しい大きさ・音声ありになる |
| `edge.spec.js` | 小さい・短い・長い動画、4K、音声の種類（音声なし・MP3・Opus・5.1ch・読めない音声が一緒）、WebM、HEVC、壊れたファイル、ファイル名の指定 |
| `strip.spec.js` | 位置情報・音声を取り除く必要があるときは元の動画をそのまま渡さないこと、全体かどうかの判定、トリミングのみ（再圧縮なし） |
| `probe.spec.js` | 予圧縮：予想の出し方（実測の平均・切り出したときの大きさ・目安の秒数）、押したときに予圧縮を使う条件と切り出した長さ、設定を変えたときのやり直し |
| `ui.spec.js` | 圧縮後・やり直し・キャンセルの画面の状態、ファイル名の例の更新、設定の保存、使い方の枚数 |
| `settings.spec.js` | 設定の保存・読み込み・初期値に戻す、URL の読み取り（別名・範囲外の値を含む）と作成、以前の形式で保存した設定の読み込み |
| `robustness.spec.js` | 別のアプリへの切り替え（デコーダーが固まったときの案内、iPhone で圧縮中に出す注意）、Android で読めないとき、互換モードの失敗・キャンセル・待ち受けの後片付け、画面を暗くしない設定 |
| `sw.spec.js` | Service Worker のキャッシュの削除範囲、オフラインでの起動（従来の画面を含む）、一度開いた説明書の画像をオフラインで表示できること |
| `selftest.spec.js` | 自己テストのページ（`selftest.html`）の自動テスト・予圧縮のテスト・新しい画面（3ステップ）のテスト・手元の動画のテストが最後まで動き、失敗がないこと |
| `easy.spec.js` | アプリの画面（3ステップ）：2択それぞれの設定（解像度・fps・モード）、720p・1080p ではない動画は元の解像度のまま、2 のその動画だけの解像度・fps・圧縮方法、「詳しく設定する」の設定のステップと保存、URLの設定で開いたとき、ステップの切り替え（圧縮後・キャンセル・戻る）、圧縮不要の動画、予圧縮の即出力、2択は保存設定を変えないこと、従来の画面との行き来（ほかのファイルのテストは従来の画面 `/old` で行う） |

- 中身の処理は、テストを動かす Chrome のものです。Android・iPhone は画面の大きさと名乗りを似せているだけなので、実機での確認は別に必要です。
- 別のアプリへの切り替えや、端末が動画を読ませてくれない状況などは、ブラウザの関数を差し替えて同じ状況を作っています。
- AAC で書き出せるか（Linux の Chrome はできない）、HEVC を読めるかは端末によって違うので、どちらでも正しい結果になるように確かめています。

### 実機での自己テスト（`selftest.html`）

iPhone・Android の実機では、`https://maka-u20mb.pages.dev/selftest.html` を開くと、その端末で圧縮を試せます（どこからもリンクしておらず、検索にも出ません）。

- **自動テストを始める**：テスト用の動画（720p・1080p60・縦長・小さい・とても短い）をその場で作り、本番と同じ画面を iframe で開いて、
  解像度・fps・音声（書き出した音声を読めるかも）・目標サイズ・元のまま渡す・トリミング・トリミングのみ（再圧縮なし）・互換モード・480p（新しい画面の 2 の解像度で選ぶ）の14件を圧縮して判定します。
- **別のアプリへの切り替えを試す**：1分の動画を圧縮している間に、手でほかのアプリに切り替えて戻り、最後まで圧縮できるかを判定します。
- **予圧縮を試す**：720p・30秒のテスト用の動画を作り、予圧縮まわりを6件判定します。読み込んだら全体を予圧縮して予想（「予圧縮済み」・即出力の大きさ）を出すこと、済んでから押すと範囲を切り出してすぐ結果にすること（予想と実際の大きさの差も出す）、途中で押しても範囲の始まりを越えていれば範囲の終わりまで続けて使うこと、範囲の始まりまで届いていなければ使わずに範囲だけを圧縮すること、「◯MB以内」でも目標の95〜100%なら使うこと、設定（指定ビットレート）を変えたらやり直すこと。端末が速く、途中で押す場面を作れなかったときは「注意」になります。画面の入力欄は `change` を送らずに変えるので、保存してある設定は変わりません。
- **新しい画面（3ステップ）を試す**：設定なしでアプリの画面を開き、画面のボタンを押してステップを進め、9件判定します。
  「なるべく圧縮」で 1 → 2 → 3 と進み 720p・30fps になること、「範囲を変えてやり直す」で 2 に戻って圧縮し直せること、3 で別の動画を選ぶと 2 に戻ること、
  「画質優先（20MB以内）」で20MB以下の動画は圧縮せずに 3 へ進め、範囲を決めると元の画質・fps のまま切り出すこと、
  「詳しく設定する」で設定のステップが入り「変更」で戻れること、URL に設定があれば（ショートカット）2 から始まりその設定で圧縮すること、
  圧縮中の「キャンセル」で 2 に戻ること、予圧縮が済むと 2 に「◯MBで即出力」が出て予圧縮から切り出すこと、最後に保存してある設定が変わっていないこと。
- **手元の動画でも試す**：iPhone で撮った HEVC・HDR・縦向きの動画など、選んだ動画を 720p・1080p・480p（新しい画面の 2 の解像度で選ぶ）で圧縮して判定します（720p・1080p ではない動画は、新しい画面では元の解像度のまま圧縮するので「注意」にします）。
- 「新しい画面を試す」以外は、アプリの画面（3ステップ）を URL の設定つきで開きます（「詳しく設定する」で 2 から始まる）。
  `selftest.html?page=old` で開くと、従来の画面（`old.html`）で試します。
- 結果は「結果をコピー」で、失敗した項目の診断情報ごとコピーできます。
- 設定は URL で渡すので、その端末に保存してある設定は使わず、変えもしません。動画は端末の外に送りません。

## プライバシー

- **動画は端末の外に送りません。** 圧縮はブラウザの機能を使って端末の中だけで行います（読み込めるのはこのサイトのファイルだけに制限しています：`public/_headers` の CSP）。
- ページを開くときは、ほかのWebサイトと同じく、配信元の Cloudflare が IP アドレスやアクセス日時などを扱います（[Cloudflare のプライバシーポリシー](https://www.cloudflare.com/privacypolicy/)）。
  このサイト独自のアクセス解析（計測用のスクリプト）や広告は入れていません。
- 設定（詳細設定、ファイル名の自由入力など）は、この端末のブラウザ内（localStorage）に保存し、外には送りません。
- 「現在の設定を記憶したURL」には設定が入ります（ファイル名の自由入力の文字も含みます）。URL を人に渡すときは注意してください。
- 共有・保存は利用者の操作で行い、共有シートで利用者が選んだアプリに渡ります。
- 診断情報は画面に表示するだけで、自動では送りません。送るかどうかは利用者が決めます（中身は端末の種類と処理の経過で、動画やファイル名は含みません）。
